## 1b. 密钥脱敏（与上游的差异）

上游 `business.mjs` 逆向时内置了四个第三方服务的真实凭据。本仓库**已将其全部移除**，替换为环境变量覆盖（`tools/build-app.mjs` 构建时自动执行，防呆校验防止漏脱敏）：

| 渠道 | 原状态 | 脱敏后 |
|---|---|---|
| Loomy（讯飞） | 硬编码 AccessKeyId/Secret | `OFM_LOOMY_ACCESS_KEY_ID` / `OFM_LOOMY_ACCESS_KEY_SECRET` |
| Raccoon（小浣熊） | 硬编码手机号加密 secret | `OFM_RACCOON_PHONE_CIPHER_SECRET` |
| Gemini | 硬编码 OAuth Client Secret（Client ID 为公开信息，保留） | `CMDC_PAK_GOOGLE_CLIENT_SECRET` |

未配置这些变量时，对应渠道不可用——这是**预期的安全权衡**，不影响其余 25 个模型与其余全部功能。如确需使用，请自行从各产品官方渠道申请凭据并配置。除这三处外，`app/` 与上游逐字节一致（仅 12 处相对导入路径改写）。

## 2. 免费额度的使用边界

四条通道的模型来自不同上游的免费额度，各上游条款独立：

- **匿名免费通道 / Kilo 免费池**：无凭证直连。上游随时可能调整闸门（事实上匿名车道已被 OpenCode 的「仅限 OpenCode 内使用」指纹检测部分拦截，属上游策略而非本项目缺陷）。适合一次性、非敏感任务。
- **十三个账号渠道**：需要用户本人登录各产品账号（Qoder、TRAE、Cline、Gemini 等），用的是**你账号自己的**免费额度。请仔细阅读各产品关于 API/客户端使用的条款；将账号额度用于官方客户端之外的场景可能存在违约风险，后果由使用者承担。
- **EAC 协付通道**：GitHub 授权 + 资源池，按上游规则使用。

**不要把本服务包装成公开售卖的 API**。免费额度按本机出口计量，聚合转发并对外经营很可能同时违反多个上游条款。

## 3. 隐私

- **Kilo 免费池的提示词可能被上游记录并用于改进其服务**（上游模型卡与 README 均有此声明）。本项目在管理页面统计中不保存提示词与回答，但请求内容必然经过上游——**不要发送敏感信息**。
- 本地统计只记录 token 数、耗时、成功率，不含内容。
- 数据目录含**明文凭据**（`channel-credentials.json`、`eac-user.json`）与 API Key（`settings.json`）。备份文件等同账号权限，传输与存储需加密；服务器被入侵等于这些账号被入侵。

## 4. EAC 授权闸门

上游用 AES-256-GCM 密封协付车道凭据，并设有明确的宿主/授权判定。**本重构未绕过、未削弱任何闸门**：`eac.mjs` 与上游一致，授权流程原样保留。如发现本项目衍生版本去除了授权校验，那已不是本项目的分发内容。

同理，请勿尝试对混淆代码（字符串加密、导入表哈希、控制流平坦化）做脱壳后二次分发——上游 `README` 明确禁止破解、盗版密钥与绕过授权。

## 5. 服务器暴露面的自管责任

- 服务设计为**单用户本机使用**。部署到服务器等于你把一个持有多个上游账号凭据的聚合网关放上了公网，请自行评估：
  - 至少置于 TLS 反代之后（本项目提供配置）；
  - 用安全组/防火墙限制来源 IP；
  - 管理页面不要暴露给公网（或用 VPN/内网可达）；
  - 定期轮换 API Key、审查 `stats.json` 与渠道请求日志；
  - 数据目录纳入备份策略（同时注意备份本身含明文凭据）。
- 上游「自动签到」「账号池轮换」等自动化行为在不同账号条款下的合规性，由使用者自行确认。

## 6. 上游网络波动

免费额度池的可用性不受本项目控制：模型可能随时下线、限流、要求验证。本项目的行为是**忠实透传上游应答**（错误 envelope 保持一致），不缓存、不伪装成功。
